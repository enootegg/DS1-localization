## 2. Як працює DLL

### 2.1. Що робить гра

DS1 тримає всі ресурси в архівах `data\*.bin`. Імена архівів не довільні: гра при старті
будує таблицю зі **144 відомих імен** (12 категорій; 11 з них × 12 мов + базовий, остання —
`Patch` — без мов) і монтує з теки лише ті `.bin`, чиє ім'я є в таблиці. Тому зайвий `.bin`
у `data\` гра мовчки ігнорує — і саме тому інсталятор переписував наявний архів.

Останнє ім'я таблиці — `Patch` = `59b95a781c9170b0d13773766e27ad90.bin`. Його гра монтує
окремо, останнім, додаючи в кінець списку. Файл за хешем шляху шукається **від кінця списку
до початку**, тож `Patch` перекриває все.

### 2.2. Що робить DLL

Гра імпортує системну `winhttp.dll`; замість неї вантажиться наша з кореня гри, яка всі
справжні виклики передає далі (QuickDllProxy), а під час завантаження ставить один хук:

1. Хукає `PackFileDevice::MountAll(this, "source:data/")` — функцію, що монтує архіви зі списку.
2. Після того як гра змонтувала своє, для кожного `localization\*.bin` (за абеткою) викликає
   функцію гри `PackFileDevice::Mount(this, path, -1)`. `-1` = «додати в кінець», точно як гра
   робить для `Patch`. Шлях — `source:localization/<ім'я>.bin` (`source:` — корінь гри).
3. Наш архів опиняється після `Patch`, тому його файли перекривають усе. Якщо архівів у теці
   кілька, виграє пізніший за абеткою.

Рядок шляху гра приймає у власному типі `String` (вказівник на символи, перед ним заголовок
`{refcount, crc, length, capacity}`). DLL збирає такий рядок сама: порівняння в `Mount` іде
за вказівником, довжиною й `memcmp`, поле `crc` не читається. Лічильник посилань виставлено
великим, щоб гра не спробувала звільнити пам'ять не зі свого алокатора.

Обидві функції шукаються за сигнатурами байтів, і хук ставиться лише коли **кожна знайдена
рівно один раз**. Інакше DLL нічого не чіпає, пише причину в лог, і гра запускається без
перекладу.

### 2.3. Лог

`ds1_localizer.log` поруч з exe, перезаписується при кожному запуску. Робочий стан:

```
Hooked, waiting for the game to mount its archives
Mounted source:localization/ds_ua.bin
```

| У лозі | Що це означає |
|---|---|
| файлу немає | DLL не завантажилась: `winhttp.dll` не в корені гри |
| `expected 1 signature match, found 0` | інша збірка exe — сигнатури треба підбирати заново (розділ 9) |
| лише `Hooked…` | у `localization\` немає жодного `.bin` |
| `FAILED to mount …` | гра не змогла відкрити архів: пошкоджений або не того формату |
| `Skipping … plain ASCII` | в імені архіву є не-латинські символи |

## 3. Локальна збірка

Потрібні: Windows, CMake + Visual Studio Build Tools 2022, Node.js 20, Python 3.13.

```
pip install -r requirements.txt
copy .env.example .env          # вписати CROWDIN_TOKEN
```

Покласти шрифти й текстури в `resources\Sources` і `resources\Sources_DSDC_Only` (вміст
`resources.zip` з R2 — ті самі теки, що в інсталятора), або вказати наявну теку через
`--resources`. Далі:

```
python scripts/build_all.py
python scripts/build_all.py --resources "<тека з Sources і Sources_DSDC_Only>"
```

Результат — `dist\Death.Stranding*.UA.<версія>.zip` і розпаковані комплекти в `dist\dc\`,
`dist\ds\`. Гра для збірки не потрібна.

Окремі кроки (те, що `build_all.py` викликає по черзі):

```
node scripts/set-version.js                 # version-info/version.txt, progress.txt
node scripts/build-localization.js          # resources/Localization/*.json з Crowdin
node scripts/build-localization.js my.csv   # те саме з локального CSV-експорту Crowdin
python scripts/build_archive.py --edition dc
python scripts/build_archive.py --edition ds
python scripts/build_all.py --csv my.csv    # уся збірка без Crowdin (версія буде "dev")
```

`build_archive.py` зупиняє збірку, якщо Decima пише про помилки (`Can't find…`,
`Unable to read…`): так у реліз не потрапить архів з невідомим грі типом чи файлом.

## 4. Збірка на GitHub

`Actions → Build Localizer → Run workflow`. Один job на `windows-latest` скачує `resources.zip`
з R2, запускає `python scripts/build_all.py` і віддає два zip; другий job публікує реліз
`v<версія>` з обома архівами.

**Секрети репозиторію** (`Settings → Secrets and variables → Actions`) — ті самі, що в
інсталятора:

| Секрет | Навіщо |
|---|---|
| `CROWDIN_TOKEN` | версія й експорт перекладу |
| `R2_ACCOUNT_ID`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY` | скачати `resources.zip` з бакета `ds-localizer-sources` |

Job збірки працює в environment `ds` (`Settings → Environments`), тож секрети можна покласти
туди. Секрети рівня репозиторію теж підійдуть — job бачить і ті, і ті.

Разом з архівами в артефакти збірки потрапляє `ds_untranslated.txt` — рядки звичайної гри,
що лишились англійською (розділ 6).

Публікації в LBK Launcher, як в інсталятора, тут немає: формат пакета інший (не exe).

## 5. Звичайна DS проти Director's Cut

DLL та сама (сигнатури збігаються в обох exe). Відрізняються дані:

- **Текст:** різні набори рядків (розділ 6).
- **Prefetch:** свій у кожної гри. Архів від DC у звичайній DS підмінив би її prefetch чужим.
- **Текстури:** усі файли в `Sources` і `Sources_DSDC_Only` зроблено з Director's Cut, а
  формат `.core` між виданнями трохи відрізняється.

### 5.1. Що відрізняється в текстурах

`.core` — це послідовність об'єктів: `хеш типу (8 байт) + розмір (4) + дані`, дані починаються
з UUID об'єкта (16 байт). UUID між виданнями однакові, а типи — ні:

| Тип | Хеш у DC | Хеш у звичайній DS | Дані |
|---|---|---|---|
| `Texture` | `3b7a8f4fbddcd834` | `a664164d69fd2b38` | однакові за будовою |
| `TextureSet` | `00b4a8881829a349` | `a321e8c307328d2e` | у DC на одне 4-байтове поле (`FFFFFFFF`) довші |

Гра, зустрівши невідомий хеш типу, не створює об'єкт. Далі перше ж посилання на нього
закінчується навмисним вильотом (`Failed to resolve link from … (Failed to find the target
object)`, у вікні помилки — `Access Violation` в потоці `Background N`).

### 5.2. Що робить `fix_types.py`

Для кожного `.core`, який є і в теці, і в грі, зіставляє об'єкти з оригіналом за UUID:

- тип інший, розмір той самий (`Texture`) → лишає наш об'єкт із перекладеним зображенням,
  підставляє хеш типу з гри;
- тип інший і розмір інший (`TextureSet`) → бере об'єкт цілком з гри. Це лише опис набору;
  зображень у ньому немає;
- для звичайної DS видаляє файли, яких у грі немає взагалі (тир, тренування бою тощо).

Для Epic DS 1.0.8: підставлено 284 хеші, 58 наборів узято з гри, 28 файлів відкинуто. На
Director's Cut нічого не змінюється.

Правило загальне, тож нова текстура з DC підженеться сама. Чого воно **не** вміє: якщо в
DC-версії інший розмір самої `Texture` (інша роздільність чи формат), об'єкт буде взято з
гри — текстура мовчки лишиться англійською. Сигнал — число `об'єктів узято з гри` у виводі
збірки: зараз це рівно 58 `TextureSet`; якщо зросло — дивитись, що додалось.

## 6. Текст

Crowdin (проєкт 749381, файл 22) містить рядки **Director's Cut**: 26 044 рядки в 432 файлах,
ключ — `шлях/до/файлу.core@@@@UUID`. `build-localization.js` робить з експорту два файли:

**`localization.json` (Director's Cut)** — CSV один в один, плюс режим показу з
`data/show_dc.json`. Crowdin режиму не зберігає, а в грі 146 рядків мають не `auto`:
116 `always` (показуються навіть з вимкненими субтитрами — титри пісень, назви епізодів) і
30 `never`. Інсталятор ставив усім `auto`, через що ці 116 зникали при вимкнених субтитрах.

**`localization_ds_not_dc.json` (звичайна гра)** — 22 566 рядків у 402 файлах:

| Рядків | Звідки переклад |
|---|---|
| 22 321 | той самий файл і UUID є в DC — береться переклад DC |
| 245 | є лише у звичайній грі — див. нижче |

Для 245 власних рядків звичайної гри (`data/ds_only_strings.json`) переклад шукається так:

1. `target` у `ds_only_strings.json`, якщо заповнений (зараз 44);
2. інакше переклад DC для **того самого англійського тексту** — спершу в тому ж файлі, потім
   будь-де, і лише якщо він однозначний (зараз так знаходиться 137 рядків);
3. інакше рядок лишається англійською (64) і потрапляє в `ds_untranslated.txt`.

Усі 64 неперекладені — те, чого гравець не бачить: 56 рядків налагоджувального меню
розробників (`ds_prototype`) і 8 рядків з однієї крапки.

Звідки взято 44 заповнені вручну: 2 були в старому `localization_only_in_ds_not_dc.json`;
21 назва вантажу (`Metals (M)` → `Метали (M)`) складена з перекладу матеріалу в DC;
20 описів вантажів — це переклад DC того самого опису без кінцевого речення «Це вантаж для
доставки, і Сем не може його використати», якого у звичайній грі немає; примітка до оновлення
1.07 — заголовок плюс перекладена в DC підказка про експорт збережень. Вони не оновляться
самі, якщо перекладачі змінять ці формулювання в Crowdin.

Якщо після оновлення гри з'являться нові неперекладені рядки, видимі гравцеві:

```
python scripts/ds_only_json.py export    # -> ds_untranslated.json у корені
... заповнити поля "translation" ...
python scripts/ds_only_json.py import    # -> scripts/data/ds_only_strings.json
```

Описи, що відрізняються лише розміром партії, там зведено до одного запису з `{size}`.

`scripts/verify_text.py` (його викликає `build_all.py` наприкінці) читає текст назад із
зібраних архівів і звіряє кожен рядок з перекладом і з оригіналами в `gamedata/`: чи кожен
рядок гри є в перекладі, чи в архіві саме той текст і режим показу. Перевіряються файли
`simpletext.core` і `sentences.core` — ті самі, які експортує Decima і які є в Crowdin.
До цього в інсталяторі з 245 рядків потрапляли лише 84 (через
`localization_only_in_ds_not_dc.json`, з них перекладено 2), а 161 — зокрема всі назви
вантажів-матеріалів і діалоги експорту збережень — мовчки відкидались.

Дані в `scripts/data/` знято з гри командою Decima `localization export`; `source_show_ds.json`
— це англійський текст і режим показу всіх рядків звичайної гри. Після оновлення гри їх
треба перезняти (розділ 7).

Рядок `Версія перекладу: X` у `ds_system/simpletext.core` збірка замінює на поточну версію.

## 7. `gamedata/` — що взято з гри і як це оновити

Decima не може працювати без гри: їй треба знайти exe, взяти Oodle і прочитати з архівів ті
файли, які вона патчить. Тому збірка збирає «міні-гру» з того, що лежить у `gamedata/`:

| Файл | Що це | Розмір |
|---|---|---|
| `<видання>/base.bin` | архів з оригінальними текстовими `.core` (467 у DC, 433 у DS) і `prefetch` | ~32–34 МБ |
| `<видання>/originals.json` | для кожного файлу з Sources: чи є він у грі, і UUID/тип/розмір його об'єктів — цього досить `fix_types.py`; 58 `TextureSet` звичайної гри збережено цілком | ~1 МБ |
| `oo2core_7_win64.dll` | бібліотека Oodle з гри (однакова в обох виданнях) | 1 МБ |

Перезняти треба, коли **гра оновилась** або **до Sources додано новий файл** (інакше збірка
зупиниться з підказкою). Потрібна гра з оригінальними файлами:

```
python scripts/extract_gamedata.py --edition dc --game "<корінь Director's Cut>"
python scripts/extract_gamedata.py --edition ds --game "<корінь звичайної гри>"
```

Звірити, що збірка без гри й на справжній грі дає одне й те саме:

```
python scripts/build_archive.py --edition ds --game "<корінь гри>" --out work\check.bin
```

## 8. Формат архіву (коротко)

Повний опис — `Packfile.java` у [Decima Workshop](https://github.com/ShadelessFox/decima);
читання на Python — `scripts/packfile.py`.

- Заголовок 40 байт: magic `0x20304050` (відкритий) або `0x21304050` (шифрований), далі
  розміри й кількість записів.
- Таблиця файлів (32 байти на запис): хеш шляху, зсув і розмір у розпакованому потоці.
  Хеш шляху = MurmurHash3 x64-128 (seed 42) від шляху з завершальним нулем, перші 8 байт.
  Шлях — без `cache:`, з `/` і з розширенням `.core` або `.core.stream`.
- Таблиця блоків (32 байти): розпакований і стиснений діапазони; блок до 256 КБ, стиснення
  Oodle.
- У шифрованих архівах заголовок і таблиці XOR-яться з MurmurHash3 від ключа, дані блоків —
  з MD5. Наші архіви не шифровані, гра приймає обидва варіанти.

```python
from packfile import Game, core_objects
game = Game(r"<корінь гри>")
data = game.read("interface/fonts/ds/sst.core")     # None, якщо файлу немає
for type_hash, uuid, size in core_objects(data): ...
```

## 9. Якщо сигнатури перестали знаходитись

Адреси (RVA) у перевірених exe:

| Функція | Steam DC 1.0.0.4 | Epic DS 1.0.8 |
|---|---|---|
| `PackFileDevice::MountAll` | `0x1924850` | `0x1774ba0` |
| `PackFileDevice::Mount` | `0x1928ac0` | `0x1778df0` |
| конструктор пристрою (викликає `MountAll` з `"source:data/"`) | `0x1921240` | — |
| заповнення таблиці 144 імен | `0x1930560` | — |

Як знайти їх у новій збірці (`scripts\re\`, потрібні `pip install capstone lief numpy`; exe
обов'язково задається змінною `DS_EXE`):

```
set DS_EXE=<шлях до exe>
python scripts\re\xrefs_strings.py "*.bin"        # єдине посилання -- всередині MountAll
python scripts\re\rng.py <початок>-<кінець>       # дизасемблювати знайдену функцію
python scripts\re\sig.py "4C 8B DC 55 ? ? 41 56"  # перевірити, що нова сигнатура унікальна
```

Орієнтири в `MountAll`: рядок `*.bin`, далі цикл, що викидає імена з `debug` і ті, яких немає
в таблиці (`cmp edi, 0x90`), і **два** виклики однієї функції — це `Mount`: перший з індексом
`[this+0x30] - [this+0x40]`, другий з `-1` (для `Patch`). `Mount` упізнається за перевіркою
magic: `lea eax, [rcx - 0x20304050]` / `test eax, 0xFEFFFFFF`.

Сигнатури лежать у `Injector::Attach()`; змінні частини (зсуви `rip`) позначено `?`.

### Як розбирати виліт гри

Гра пише `error.txt` у свій корінь. У стеку перша адреса з exe (`0x0001418DE7C2` → RVA
`0x18DE7C2`) — місце вильоту:

```
python scripts\re\rng.py 18de680-18de800
```

У DS більшість «вильотів» — навмисні (`mov dword ptr [0], 0xDEADCA7`), і за кілька рядків
вище лежить текст причини. Саме так знайдено проблему з типами текстур.

---

## 10. Головні правила

1. **Архів DC не класти у звичайну DS і навпаки** — чужий prefetch і чужі типи текстур.
2. **`gamedata/` знімати лише з гри з оригінальними файлами.** На українізованій грі імпорт
   не побачить різниці й не створить жодного текстового файлу.
3. **Не вимикати перебудову prefetch** (`--no-rebuild-prefetch` у `build_archive.py`) — без
   нього гра читає змінені `.core` зі старими розмірами.
4. **Імена архівів у `localization\` — лише латиницею.**
5. Хук ставиться тільки при однозначному збігу сигнатур — не послаблювати цю перевірку.
6. Після зміни `Sources` запускати `extract_gamedata.py` для **обох** видань і комітити
   оновлені `originals.json`.

---

## 11. Що не зроблено

- **Xbox / Game Pass:** там `packed_GDK\` замість `data\`, і exe інший. Чи знайдуться
  сигнатури й чи завантажиться проксі `winhttp.dll` — невідомо.
- **Steam-версія звичайної DS:** перевірено лише Epic-збірку 1.0.8.
- **Linux / Proton:** проксі-DLL зазвичай потребує `WINEDLLOVERRIDES="winhttp=n,b"`; не
  перевірялось.
- **Збірка під Linux:** Decima в `tools/decima` і Oodle — лише Windows.
